# 材质还原流程与 ParkingLots 整改

## 主方案与补充方案（分析版本 23）

新任务默认 `legacy_main_v1`，GUI「材质工作流」选择「主方案：旧版稳定配方＋纹理优化」。没有此字段的历史任务仍按原语义流程读取，不自动迁移，不后台替换已经导入的资源。

| 入口 | 行为 | 边界 |
|---|---|---|
| 主方案 | 简单节点直接转换；复杂程序字段局部烘焙，保留旧版闭包混合和法线路径；失败/超时再尝试旧式完整 PBR 兜底 | 不自动补修白模，不因新闭包功能改变整场景 |
| 补充方案（实验性） | GUI「补修白模（实验性）」按失败记录的精确 ID 勾选；重新生成候选，只更新原关卡的对应 USD 材质绑定 | 正常白色、仅需复核以及同名的成功记录不自动入选；候选失败保留原绑定 |
| 撤销补充方案 | GUI「撤销上次白模补修」恢复该批根层、材质记录与报告 | 根层或记录有后续修改时拒绝覆盖，保留还原点 |

主方案保留旧版地板原贴图法线和实时闭包混合、蓝色鼓身基础 PBR（清漆等省略明确计为近似）、镲片局部高度字段加 Bump 的路径。不会默认套用语义版的全闭包原生法线或位移适配。

音箱的两处优化限定在主方案：Checker 直接映射节点并按屏幕导数过滤，避免先烘焙丢失网格；非平铺 Noise 基础色按源 UV/Mapping/频率提高局部采样，上限为配置分辨率四倍且不超过 4096。超过上限记录复核，不擅自降低源频率。法线高度字段和平铺地面不应用这条颜色采样优化。

静态体积独立于二维 PBR 贴图流程：均匀 World 体积映射环境雾，封闭网格程序体积采样成 3D VDB，已有 VDB 冻结选定帧，UE 使用 SVT/Heterogeneous Volume。保留单位、变换、密度和颜色，记录 `static_frame` 与参考帧。开放容器、无法可靠采样的依赖和体积失败单独报告；动画体积播放不在本轮范围。

补充方案要求源哈希、参考帧、主场景记录、导入报告和 USD 根层仍对应；只允许必要 UV/坐标覆盖，不写顶点位置和拓扑。现有 UV 不改写；所需源 UV 不同则追加补修通道。原求值几何不匹配、共享记录的几何/UV 无法验证或超过 UE 四个 UV 通道时跳过。既有成功材质记录与资产文件必须保持不变。新资产隔离到 `MaterialRepairs/B_<哈希>`，长目录使用独立短命名空间 `/Game/MMDBridgeRepairs/`；批次回执记录实际路径。原根层追加强覆盖层；提交前验证实际 UE 组件槽位及新增 UV 通道，保留根层、关卡和元数据还原点。提交日志支持中断后恢复；检测到后续用户编辑时停止覆盖。

普通导入在结束时保存本任务 Stage 的生成网格及缓存，补修仍拒绝未保存的用户关卡/资源。共享网格的多个补修候选通过只读会话层统一分配新增 UV，避免候选互相覆盖坐标。每轮候选构建和原场景补修均保持 `needs_review`，技术检查不会代替画面验收。

## 语义方案兼容流程（语义计划版本 1）

| 判断 | 默认流程 |
|---|---|
| 有效图全部由已适配节点、查找表和源数据表达（含 Checker） | 直接节点转换，不生成冗余贴图 |
| 仅一两个静态字段需要适配 | 只烘焙字段，保留其余节点 |
| Fresnel/双面等实时混合，分层、清漆、SSS、透射、位移或体积语义 | 保留闭包和实时依赖；复杂静态字段局部烘焙；缺少适配时明确报告 |
| 平铺大表面 | 保留坐标与纹理密度，局部字段缓存，不因尺寸大就切分整个表面 |
| 单层静态普通 PBR 的至少三个字段需要适配 | 完整 PBR 烘焙；仅在这条路线下考虑整物体或分块 |
| 完整烘焙路线且非平铺物体最长边至少 8 米或包围盒最大投影面积至少 64 平方米 | 分块烘焙；阈值是布局启发式，不是材质语义判定 |
| 源坐标不可靠、动画/驱动或字段缺少安全适配 | 拒绝猜测或静态冻结，保存失败原因并继续其他独立材质 |
| 透光还原失败或有匹配源哈希的视觉不符记录 | 优先局部兜底；允许不透明着色降级，但 Transparent/Alpha 裁切覆盖仍独立保留 |

重复数量只决定资源复用计划，不改变材质语义或转换路线。至少 8 次使用触发共享字段复用建议；真正的缓存命中仍须验证有效图、纹理内容、源 UV、Generated/对象/世界坐标及几何。不同几何的法线图不能盲目共用。全局强制节点、混合、烘焙选项保留；强制烘焙的实时/分层损失必须记录，不能绕过不可靠数据或动画检查。

自动策略禁止把湿面 Fresnel 等实时混合固定成 50%。超时或失败先缓存安全静态字段；局部兜底后仍无法保留实时或分层结构时，明确报告失败。用户显式选择完整烘焙、或已允许的透光不透明降级，才可采用有记录的有损投影。不烘焙灯光和阴影。关闭兜底不影响主动选择的普通静态 PBR 烘焙。

原生提取输出先分析其节点结果，不能将未连接输出插槽的默认值当作常量。纯静态单层 PBR 烘焙和多闭包投影分别报告；导入成功、转换正确性、视觉验收仍是独立状态。

节点缺少 UE 直接适配不等于无法烘焙：静态 BOX/UDIM 投影允许原生局部烘焙。每个待缓存节点按自身依赖判断，不能用整个 Fresnel 混合因子的 view 域误拒绝其中的静态 Noise。静态 Bump Normal 可通过原生法线/世界空间向量字段处理；光线、视角、动画及未知字段仍禁止静态缓存。失败记录保留具体阻塞节点、输出、组路径和数据域。

这些规则用于下一次场景转换，已经导入的旧版和 03 场景不会被后台替换。新的空间分块需要从源场景建立新任务；旧冻结几何的材质重做会保留已有几何划分。

材质转换正确性、导入成功、视觉验收是三个不同结果。占位材质导入成功不能抹掉源材质转换失败；跨渲染器外观必须保留人工复核。

## 策略

| 策略 | 处理方式 | 适用范围与限制 |
|---|---|---|
| 节点转换 | 图片、计算和已支持的着色闭包直接映射到 UE | 保留实时视角判断；Checker 和 Backfacing 已直接映射 |
| 混合转换 | 保留闭包混合结构，只缓存静态程序字段 | 玻璃、透射、清漆、SSS 保留结构；不能把视角、时间或光线依赖烘焙成固定图 |
| 原生闭包法线 | 单独连接对应闭包的 Normal，使用 Cycles NORMAL 烘焙 | Bump 采用世界空间导数；不能用整个混合表面的法线替代某个分支的法线 |
| 完整 PBR 兜底 | 转换失败或超时后烘焙基础色、金属度、粗糙度、法线、透明度、自发光，直接连接 UE | 静态表面可继续导入；多闭包投影、透射和分层效果损失必须明确记录 |
| 占位 | 最后生成灰色材质，继续独立工作 | 明确计为失败，记录物体、材质和原因 |

120 秒预算按单材质协作检查；触发后进入分级兜底。单个原生 API 调用无法在调用内部被这个预算中断，局部或完整兜底不共用已耗尽的节点转换预算。强制节点不触发烘焙。

## 已确认问题与改动

| 部分 | 原因 | 改动 |
|---|---|---|
| 人物立牌 | 混合 Glass 闭包和 Backfacing 缺少转换 | Glass 混合树、透射、IOR、颜色与实时双面朝向分别保留 |
| 雨伞 | 通用 Principled Transmission 不完整 | 构建原生透射闭包，采用彩色透射混合模式，保留复核 |
| 清漆 | 完整 PBR 无法保留第二层高光 | 独立清漆层，保留权重、IOR、颜色、粗糙度与独立法线 |
| 树皮、树叶 | SSS 缺失；原生 Normal 被导数安全检查误拒绝 | 保留散射半径与尺度、权重闭包混合；修复原生法线检查 |
| 几何节点镲片 | 宿主原始顶点与最终几何不对应 | 按已验证的 Cycles 求值网格 ORCO/纹理空间保存 Generated，不猜测宿主索引 |
| Laney 前面板 | 两组高频 Checker 局部烘焙可能损失细纹 | 直接构建三轴 Checker，保留源 Mapping、负坐标奇偶性和边界行为；近远景仍需复核 |
| 位移 | 只处理主要闭包，且轮廓损失未报告 | 将 bump-only 高度作用于所有有效闭包；真实几何位移缺失明确记录 |
| 远距遮罩 | 只调整 MIP 偏移，没有覆盖率保存 | 直接标量遮罩使用独立覆盖率 MIP 资源；复杂组合遮罩继续复核 |
| OCIO | 中文文件路径读取失败，资产存在仍被当成成功 | ASCII 内容哈希缓存，原生处理器正向与无效配置验证；视口自动恢复，可在 GUI 取消 |
| 深目录资产 | UE 原生导入器缩短名称，程序按原名查找 | 文件路径预算与哈希名称；USD 引用、创建、加载、复用使用同一规则 |
| 失败后的占位 | 未保存的程序构建被当成用户编辑 | 仅本轮新建的受管理对象允许重建；已有用户编辑保护继续生效 |
| 渲染时灰色替代 | 材质缺少 Nanite / 实例使用标记，编译成功仍可能被默认材质替代 | 构建时补齐使用标记；渲染回执扫描实际替代警告，不能报告成功 |

## 代码职责

- `material_contract`：源闭包参数、功能标记、转换状态、问题记录、资产名称预算。
- `material_plan`：纯 Python 语义路线、资源复用与分级兜底；`blender_material_plan` 从有效源图收集事实，供分块预检和实际转换共同使用。
- `material_graph`：有效图分析、数据依赖、函数与中间表示。
- `blender_materials` / `blender_pbr_bake`：转换编排、局部字段、逐闭包原生法线和完整兜底。
- `scene_shader_data` / `blender_usd`：源坐标载体、分块与 USD 材质绑定。
- `ue_materials`：着色闭包、角色明确的贴图资源、原生编译与受管理资源保护。
- `ocio_cache` / `ue_appearance`：便携颜色配置、处理器验证、MRQ 与视口配置。
- `material_results` / GUI：按物体和材质查看策略、转换状态、视觉状态、原因与兜底过程。

`conversion_status` 为 `converted / approximated / placeholder / failed`。`visual_status` 独立；技术检查通过不会自动成为人工视觉验收通过。

## 当前限制

当前工程采用 Blendable GBuffer，会合并闭包并限制部分 F90/MFP 响应。程序保留可编辑节点结构，报告此限制，不自动修改项目 GBuffer 模式。源随机游走 SSS 与 UE 扩散模型、屏幕折射、复杂透明覆盖率及真实着色器位移仍需要视觉复核。

验证使用原始 ParkingLots `.blend`，源文件不保存、不改写；新场景导入隔离目录，旧场景保留。原场景仅修复其受管理 OCIO 配置文件路径。

## 历史原生视觉验证（ParkingLots 03）

完整源相机帧的对照暴露了尚未解决的外观问题：立牌透射混合树偏白，雨伞透射过弱。贴图绑定与源 PNG Alpha 有效；正面分支对照仍偏白，单闭包诊断能显示人物，参数混合诊断仍有绿边和透明覆盖错误。因此这些记录保持 `needs_review`，并记录 `appearance_mismatch`，不能称为可靠还原。诊断材质仅存在于隔离测试目录，最终场景保留源透射结构。

源中 19 个空宿主已单独求值检查：12 个有导出的生成实例，另 7 个在源求值结果中没有表面面片（其中两个是线段曲线）；不能把它们一律当成丢失材质或丢失网格。
