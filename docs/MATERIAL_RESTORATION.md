# 材质还原流程与 ParkingLots 整改

## 当前自动策略（分析版本 20）

| 判断 | 默认流程 |
|---|---|
| 简单计算、或有效图全部由已适配节点表达（含 Checker） | 直接节点转换，不生成冗余贴图 |
| 同一源材质实际实例使用至少 8 次 | 优先节点；不兼容静态字段按几何语义复用缓存，不逐实例烘焙 |
| 其他少量使用的复杂表面 | 优先从源有效图提取基础色、粗糙度、金属度、法线等，完整 PBR 贴图直接连接 |
| 复杂物体最长边至少 8 米或包围盒最大投影面积至少 64 平方米 | 分块烘焙；其余整物体烘焙 |
| 透光、半透明表面 | 先尝试节点；转换失败或有匹配源文件哈希的视觉不符记录时，允许不透明 PBR 降级 |

这里的重复使用按共享源材质和真实实例数量统计，不做图像相似度猜测。缓存依赖坐标、几何和有效字段；不同几何的法线图不能盲目共用。全局强制节点、混合、烘焙选项仍可覆盖自动策略。

PBR 投影会损失分层与折射。视角/光线相关闭包混合使用明确记录的固定权重；不烘焙灯光和阴影。动画和未知动态依赖仍会拒绝静态冻结。关闭兜底不影响主动选择的烘焙路线。

这些规则用于下一次场景转换，已经导入的旧版和 03 场景不会被后台替换。新的空间分块需要从源场景建立新任务；旧冻结几何的材质重做会保留已有几何划分。

材质转换正确性、导入成功、视觉验收是三个不同结果。占位材质导入成功不能抹掉源材质转换失败；跨渲染器外观必须保留人工复核。

## 策略

| 策略 | 处理方式 | 适用范围与限制 |
|---|---|---|
| 节点转换 | 图片、计算和已支持的着色闭包直接映射到 UE | 保留实时视角判断；Checker 和 Backfacing 已直接映射 |
| 混合转换 | 保留闭包混合结构，只缓存静态程序字段 | 玻璃、透射、清漆、SSS 保留结构；不能把视角、时间或光线依赖烘焙成固定图 |
| 原生闭包法线 | 单独连接对应闭包的 Normal，使用 Cycles NORMAL 烘焙 | Bump 采用世界空间导数；不能用整个混合表面的法线替代某个分支的法线 |
| 完整 PBR 兜底 | 转换失败或超时后烘焙基础色、金属度、粗糙度、法线、透明度、自发光，直接连接 UE | 静态表面可继续导入；多闭包投影、透射和分层效果损失必须明确记录 |
| 占位 | 最后生成灰色材质，继续独立工作 | 明确计为失败，记录物体、材质和原因 |

120 秒预算按单材质协作检查；触发后进入兜底。单个原生 API 调用无法在调用内部被这个预算中断，兜底烘焙不共用已耗尽的节点转换预算。

## 已确认问题与改动

| 部分 | 原因 | 改动 |
|---|---|---|
| 人物立牌 | 混合 Glass 闭包和 Backfacing 缺少转换 | Glass 混合树、透射、IOR、颜色与实时双面朝向分别保留 |
| 雨伞 | 通用 Principled Transmission 不完整 | 构建原生透射闭包，采用彩色透射混合模式，保留复核 |
| 清漆 | 完整 PBR 无法保留第二层高光 | 独立清漆层，保留权重、IOR、颜色、粗糙度与独立法线 |
| 树皮、树叶 | SSS 缺失；原生 Normal 被导数安全检查误拒绝 | 保留散射半径与尺度、权重闭包混合；修复原生法线检查 |
| 几何节点镲片 | 宿主原始顶点与最终几何不对应 | 按已验证的 Cycles 求值网格 ORCO/纹理空间保存 Generated，不猜测宿主索引 |
| Laney 前面板 | 两组高频 Checker 局部烘焙可能损失细纹 | 直接构建三轴 Checker，保留源 Mapping、负坐标奇偶性和边界行为；近远景仍需复核 |
| 位移 | 只处理主要闭包，且轮廓损失未报告 | 将 bump-only 高度作用于所有有效闭包；真实几何位移缺失明确记录 |
| 远距遮罩 | 只调整 MIP 偏移，没有覆盖率保存 | 直接标量遮罩使用独立覆盖率 MIP 资源；复杂组合遮罩继续复核 |
| OCIO | 中文文件路径读取失败，资产存在仍被当成成功 | ASCII 内容哈希缓存，原生处理器正向与无效配置验证；视口自动恢复，可在 GUI 取消 |
| 深目录资产 | UE 原生导入器缩短名称，程序按原名查找 | 文件路径预算与哈希名称；USD 引用、创建、加载、复用使用同一规则 |
| 失败后的占位 | 未保存的程序构建被当成用户编辑 | 仅本轮新建的受管理对象允许重建；已有用户编辑保护继续生效 |
| 渲染时灰色替代 | 材质缺少 Nanite / 实例使用标记，编译成功仍可能被默认材质替代 | 构建时补齐使用标记；渲染回执扫描实际替代警告，不能报告成功 |

## 代码职责

- `material_contract`：源闭包参数、功能标记、转换状态、问题记录、资产名称预算。
- `material_graph`：有效图分析、数据依赖、函数与中间表示。
- `blender_materials` / `blender_pbr_bake`：转换编排、局部字段、逐闭包原生法线和完整兜底。
- `scene_shader_data` / `blender_usd`：源坐标载体、分块与 USD 材质绑定。
- `ue_materials`：着色闭包、角色明确的贴图资源、原生编译与受管理资源保护。
- `ocio_cache` / `ue_appearance`：便携颜色配置、处理器验证、MRQ 与视口配置。
- `material_results` / GUI：按物体和材质查看策略、转换状态、视觉状态、原因与兜底过程。

`conversion_status` 为 `converted / approximated / placeholder / failed`。`visual_status` 独立；技术检查通过不会自动成为人工视觉验收通过。

## 当前限制

当前工程采用 Blendable GBuffer，会合并闭包并限制部分 F90/MFP 响应。程序保留可编辑节点结构，报告此限制，不自动修改项目 GBuffer 模式。源随机游走 SSS 与 UE 扩散模型、屏幕折射、复杂透明覆盖率及真实着色器位移仍需要视觉复核。

验证使用原始 ParkingLots `.blend`，源文件不保存、不改写；新场景导入隔离目录，旧场景保留。原场景仅修复其受管理 OCIO 配置文件路径。

## 本次原生视觉验证

完整源相机帧的对照暴露了尚未解决的外观问题：立牌透射混合树偏白，雨伞透射过弱。贴图绑定与源 PNG Alpha 有效；正面分支对照仍偏白，单闭包诊断能显示人物，参数混合诊断仍有绿边和透明覆盖错误。因此这些记录保持 `needs_review`，并记录 `appearance_mismatch`，不能称为可靠还原。诊断材质仅存在于隔离测试目录，最终场景保留源透射结构。

源中 19 个空宿主已单独求值检查：12 个有导出的生成实例，另 7 个在源求值结果中没有表面面片（其中两个是线段曲线）；不能把它们一律当成丢失材质或丢失网格。
