# 内置PBR角色

当前默认、六档几何和最近验证范围见 [开发状态](PROJECT_STATUS.md)；旧阶段说明另见 [实验归档](history/CHARACTER_PBR_EXPERIMENTS.md)。本页面向当前源码，旧发行 EXE 不一定包含后续更新。

在 UE 中查找参数、判断贴图开关是否生效，以及调节皮肤高光、丝袜厚度与透明模式，见 [UE 参数含义与调节指南](UE_PARAMETERS.md)。

角色母材质预设的第二项为“内置PBR角色”，新任务默认使用这一项。已有任务按保存的预设恢复，旧任务未保存预设标识时继续使用原有自动匹配行为。

新任务默认勾选“导入角色时使用柔和阴影”，导入前可以关闭；“皮肤散射默认值”默认选择“中间散射”。面部／身体散射强度默认 0.27／0.35；粉嫩度独立于散射，当前面部与所有皮肤默认均为 0.35。选择“原暖色散射”可使用先前散射配置。旧任务缺少灯光与散射选项时恢复原解释，已保存角色不自动改变。详细数值、场景灯光处理和 UE 调节方式见 [柔和阴影与皮肤散射](CHARACTER_PBR_SOFT_SHADOW.md)。

## 输入与默认行为

选择 PMX 后，在左侧“工作区 → 角色设置”点击“分析与配置材质”。窗口按原始材质槽显示名称初判类型、PMX 透明度、Sphere 模式、可关联的附带贴图及待确认项。实际转换时，Blender 按各材质使用的 UV 区域分析透明度，避免共用图集的其它区域干扰分类。对 Eyes 等含义不明确的名称，还会按实际 UV 颜色分布复核眼白类型；手动类型优先，手动更换基础贴图后不沿用旧图的颜色判断。

- 基础色优先使用 PMX 实际引用；没有基础贴图的纯色材质保留 PMX 固有色。
- 缺少法线、粗糙度、金属度等专用贴图时，使用对应材质类型的默认参数。法线回退使用随程序提供的恒定中性法线，避免把引擎示例法线的凹凸误加到角色上。
- 附带贴图只有在名称明确关联且唯一时自动绑定。LightMap、ORM 或其它打包遮罩的通道未知时，列为候选，需手动选择用途和通道。
- MatCap 跟随 PMX 启用状态，保留 Sphere 乘算／加算模式；目录里仅存在贴图不会启用。可以按槽位强制开启或关闭。
- 眼睛使用原有网格，不增加角膜几何。虹膜视差需要明确的虹膜遮罩，默认深度为零。
- 头发使用 UE 各向异性高光。附带流向图优先；没有流向图时按连通发片的几何长轴投影生成 UV 流向图，重叠或退化区域使用 U／V 主方向并标记视觉复核，可在窗口中旋转修正。
- 原 PMX 透明度和隐藏参数原样传递，透明、自发光和材质类型分别控制。参数保留后仍需检查实际画面；跨角色测试发现 Neuro 隐藏眼层在现有路线中仍可见，记录为待修项。

新准备的内置 PBR 记录采用 Alpha 接线 v1，母材质名带 `_AM1`。基础色 A × `Opacity` × 可选透明遮罩的计算结果接到最终材质输出的 **Opacity Mask（不透明蒙版）**，Opaque 母材质也保留这条连接，供实例显式改为 Masked 时使用。Opaque 模式本身仍不裁切；Masked 按阈值裁切，不能表达连续半透明。真正的 Translucent 材质同时保留 Substrate 的 Opacity 输入，皮肤的散射强度输入保持独立。

缺少 `alpha_graph_version` 的旧记录继续沿用原接线、母材质路径和缓存签名。更新源码不会自动修改现有 UE 资产；新任务或显式重新准备材质才使用新母材质，既有手工编辑仍受冲突保护。

材质分类及默认数值是可编辑预设，不能替代对未知模型的视觉检查。自动识别无法确定具体材质时，使用通用 PBR，可手动指定皮肤、头发、眼睛各层、布料、金属、皮革、塑料、橡胶和玻璃等类型。

## 分类来源与版本

分类版本为 v9，当前着色版本 v11、默认配置 v6；版本分别记录。着色 v9 的鼻部散射遮罩、眼部自发光、牙齿釉质层和半透明布料纤维光泽继续保留。当前保留皮肤暖粉色与逐槽双层高光配置，默认 v6 将面部与所有皮肤的粉嫩度统一为 0.35；新母材质名含 `_S11_D6`。缓存签名和母材质名称读取准备记录自身的版本，已准备的 v9／D3、v10／D4 和 v11／D5 记录继续使用原版本，缺少着色与默认版本的记录按 v9／D3 解释。`classify()`、19 类标识、按模型 SHA256 和原槽索引保存的覆盖格式不变。新默认用于新材质准备或用户显式应用材质，不自动迁移已有资产。

手动类型优先；自动判断依次读取原材质 `name`、PMX 日文字段 `mmd.name_j`、英文字段 `mmd.name_e`。每个字段先统一全角字符并拆分英文单词，再按规则优先级匹配。明确的原部件名优先于后面的英文导出标签，同一字段中的金属、玻璃、塑料及眼睛分层等具体规则仍优先。例如 Ribbon 配上英文 Hair 标签时使用布料，FaceBrow 使用眉毛／睫毛，安全裤使用布料，ShortsMetal 保持金属；Shoes 和普通扣件保留通用 PBR，需人工复核。

现有“来源与待确认项”区域显示命中字段、词段、手动覆盖来源和冲突提示。未识别名称、通用材质与规则冲突不会自动获得视觉验收。贴图后缀关联、局部眼白颜色复核、PMX／UV 透明度及 MatCap 来源仍分别处理；程序不会全面识别贴图中真实的物理材质。

分析窗口的材质列表用黄色文字标出未识别、规则冲突或缺失资源。选中一行，在右侧“材质类型”选择实际类型后，沿用原基础色、透明度和 MatCap，重新匹配唯一的同名辅助贴图，并更新内置微法线、织纹和粗糙度细节。文件栏的自动路径以占位文字显示，悬停可看完整路径；不会把自动来源写成手工文件覆盖。手工文件、通道和反转优先保留。手动确认类型后解除分类黄色提示，资源缺失仍保留黄色及回退诊断。

补充 `齒`、`Eyehi`、`Trousers`、`スウェット` 等已验证别名，以及日文明确的金属、玻璃、塑料、皮革和橡胶名称；例如 `スウェットパーツ(メタル)` 保持金属。`スーツ` 只表示服装用途，继续待确认。明确命名为机器人或机械模型时，“身体／body／arm”等弱部件名不再直接判为皮肤，改为通用 PBR 待确认；不会据此猜成金属或塑料。

跨角色验收目录为 `work/character_pbr_20261018/CrossCharacter_v9`。每个样本有独立工作目录和 UE 资产根，保存规则修改前的原始自动分类及贴图引用。覆盖矩阵分开记录样本存在、原生编译与画面复核，隐藏或被遮挡的槽不会仅凭类型名称算作画面通过。GenZ v8 现有资产继续冻结；对它重新分析所得的 v9 分类不会自动写入已保存的 v8 角色。

UE 5.8 的半透明玻璃明确使用 IOR 折射模式，连接折射根输入前先完成角色 usage 编译，避免新连接与旧缓存状态冲突。这是跨角色透明罩测试发现的兼容修正，后续着色版本继续保留。

## 眼睛与牙齿

默认配置 v2 将虹膜、眼白和眼睛高光的 `EmissiveStrength` 分别设为 0.35、0.20、0.30，提高阴影中的可见度；当前 v6 保留这些数值，更早配置为 0.08、0.04、0.1。可在分析窗口“自发光强度”或 UE 材质实例中调整，0 关闭。没有独立自发光图时，使用原眼部基础色作为自发光颜色，保留瞳孔、虹膜纹理和高光的对比；明确绑定自发光图时以该图为准。原透明遮罩、原 PMX 可见性、清漆层和虹膜深度遮罩继续生效。熄灯图允许这些眼层发光；关闭眼部自发光的同机位图另作零光验证。材质名中的 `_D6` 与元数据 `PBRDefaultsVersion` 区分默认配置修订；显式手动覆盖优先。

牙齿使用低强度釉质清漆和原贴图颜色，关闭表面微噪声，默认没有自发光。口腔遮挡和灯光仍可使牙齿变灰或偏色，不能仅凭口内颜色判断贴图缺失。修正分类不替换牙齿贴图，也不将其强制涂白。独立嘴唇使用面部类型，导入时优先继承共用图集的面部参数；唇色、透明度及显式手动覆盖保留，后续单槽修改仍独立。

## 皮肤、织物与水渍

当前皮肤保留原材质结构与散射距离。身体／面部的 `Roughness` 默认 0.34／0.44，`Specular` 0.42／0.35，`DetailStrength` 0.065／0.04；降低过强微法线，保留可用的原法线、基础图、透明和水渍。面部和所有皮肤的 `SkinRosiness` 默认均为 0.35；0 恢复原基础色，增大时使用暖粉色乘算，UE 的 `SkinRosyTint` 默认 (1.04, 0.25, 0.5)。不增加皮肤自发光。

不透明／遮罩皮肤和面部在分析窗口增加三个高光控制，可随配置保存并逐槽“应用材质到UE”：

| 控制 | 范围 | 身体／面部默认 | 实际作用 |
|---|---|---|---|
| `SkinHighlightWidth` 主高光范围倍率 | 0.5—2 | 0.6／0.85 | 主要高光粗糙度倍率，越大越宽 |
| `SkinHighlightSoftness` 外围高光柔和度 | 0—1 | 0.5／0.4 | 扩展第二层高光；0 与主层相同 |
| `SkinHighlightBlend` 柔光混合比例 | 0.1—0.9 | 0.45／0.65 | 第二层高光的占比，越大外围占比越高 |

实现为原生 Subsurface Profile 的双 GGX：`Roughness0 = Width`，`Roughness1 = Width + (2 - Width) × Softness`，`LobeMix = Blend`；引擎再把两个倍率乘以表面粗糙度。`Specular` 调整反射强度。范围、柔和与强度在物理高光中会互相影响，光源尺寸和角度也会改变形状，不能把这些值解释为固定的屏幕像素半径。

每个源模型和材质槽生成独立高光配置，短路径名含 `_HL11_`，长路径按资产命名规则缩短；配置绑定到材质实例 Details 的 **Override Subsurface Profile**。在 UE 打开该配置的 **Dual Specular**，可交互调整 Roughness 0、Roughness 1、Lobe Mix；无需重新导出网格。这三个程序参数存储在 Profile 中，不伪装为无效的材质实例标量。手工编辑配置后，程序缓存复用、应用和撤销会检查修改，报告冲突并保留编辑。半透明皮肤沿用原透明着色，不启用这些 Profile 控制；散射强度接近零时，引擎会逐渐淡出双层高光。

2026-10-23 的原生样本为用户提供的芙宁娜，采用独立柔光场景；测试资产和原图保存在本地 `F:/Codex_MMDBridgePBR_Skin_20261022`，不包含在仓库。该样本的服装图集和眼层存在名称冲突，试验明确只修改实际面部及裸露皮肤槽，不代表其它槽已自动分类通过，也不能外推为其它模型的视觉验收。

第5版将皮肤毛孔、布料织纹、皮革纹理和头发细节分开。皮肤与布料都带有细微粗糙度变化；布料还使用 Cloth 纤维光泽。Blender 根据网格与实际 UV 面积估算细节尺寸，显式修改“细节重复”优先于自动估算。

第6版增加“缎面／领带”和“丝袜”类型。普通不透明布料保留 Cloth 织纹与纤维光泽；领带使用较平滑的缎纹及各向异性反光；丝袜使用独立的细密针织法线、粗糙度和覆盖遮罩。纤维高光方向按实际 UV 重力方向估算，可手动旋转。

着色 v9 的半透明布料也使用 Substrate Cloth/Fuzz，保留原 PMX alpha 与表面透明光照，不再绕过纤维光泽分支。`Fuzz`、`FuzzBrightness`、`Roughness` 和织物粗糙度变化继续可调；是否适合具体服装仍需结合原纹理、法线和实际画面确认。

选择丝袜后，“丝袜织物覆盖”控制透肤程度，“丝袜侧面加密”控制掠射角处变深的程度。此效果需要半透明模式以及丝袜下面的皮肤网格。原 PMX 透明度作为覆盖倍率参与计算，原本隐藏的槽位保持隐藏；手动不透明或镂空模式不会自动改成半透明。覆盖模型是角度与针织遮罩的表面近似，没有新增纱线几何。丝袜、领带的参数仍按模型和原槽位保存，可使用单槽应用与撤销。

“丝袜厚度”在程序中提供薄／中／厚三个预设，数值分别为0.35／1／2.5。在 UE 中打开角色 stocking 材质实例，勾选 Hosiery 分组下的 HosieryThickness，即可在0至3之间连续拖动或输入任意小数，也可用动态材质实例连续赋值。程序会保留设置文件里已有的自定义数值，点击预设才替换它。

第8版将厚度改为线性覆盖倍率：先按原织物覆盖、侧面加密和PMX透明度求出标准覆盖，再乘 HosieryThickness，最后限制到0至1。厚度0隐藏丝袜表层，1保持原标准覆盖，达到1的区域完全遮蔽后不再增加不透明度。这是相对覆盖参数，不是毫米或丹尼尔数，不改变网格；最终受光亮度不等同于参数的线性值。

旧第7版把厚度放在透光指数中，最终还受PMX透明度上限限制，导致厚档正面仍透肤，侧面更黑，中间出现浅色带。此样本的MatCap关闭、镜面高光关闭及0.3mm外移对照均未消除该带，增加遮蔽才消除。第8版只改丝袜厚度的计算，保留原左右腿不同的丝袜覆盖范围。

普通布料提高绒面纤维权重、收弱光滑表面反光，并提供“纤维提亮”和“织物粗糙度变化”，黑色纤维也能有少量反光。领带保留纤维方向，同时调宽、收弱亮面高光。“皮肤粉嫩度”范围0至1，当前面部和所有皮肤默认均为0.35；0保留原基础色。原面部彩绘、鼻部散射遮罩、水渍开关均保留，粉嫩度不增加散射距离或自发光。

纤维方向使用 UE 的 [Anisotropy 和 Tangent 输入](https://dev.epicgames.com/documentation/unreal-engine/material-inputs-in-unreal-engine?lang=en-US)，半透明丝袜沿用 [Surface ForwardShading](https://dev.epicgames.com/documentation/unreal-engine/lit-translucency-in-unreal-engine?lang=en-US)。最终效果仍以固定工程的实际编译与渲染为准。

选择皮肤或面部材质后，可勾选“皮肤水渍 → 启用水滴与流痕”。默认关闭；水渍强度、水滴重复、流痕方向、水滴凸起和水面粗糙度分别可调。这些设置按当前模型与材质槽保存；“应用当前材质到UE”和撤销使用原有单槽流程。UE 材质实例对应开关为 WetEnabled（0关闭、1开启）。全角色转换配置也可通过 character_pbr_options.params.WetEnabled 指定所有皮肤槽的默认状态。

水滴与流痕使用随程序分发的确定性表面法线和遮罩，随角色 UV 保持附着，并响应真实灯光。它属于皮肤表面效果；轮廓外的水滴体积和真实水体折射需要额外几何。流痕方向按各材质的 UV 重力投影均值估算，UV 镜像、重叠或不同方向的岛仍需视觉检查，可手动旋转。

面部和身体使用独立 Subsurface Profile，明确启用 Burley 和 Mean Free Path 参数，默认红通道距离分别为0.18cm和0.32cm，避免较宽散射抹去小尺寸鼻部的明暗。源模型网格、骨架和表情保持原来源。

“鼻部等细节保留”控制平滑面部散射遮罩的作用，0 为均匀散射，1 为全部应用当前遮罩。旧自动遮罩在鼻部将散射乘到接近零，多个角色出现集中暗斑；着色 v9 对自动生成的遮罩先应用“自动散射遮罩下限”`SSSMaskFloor`。v3 按用户选择将下限恢复为 0.9，当前 v5 继续保留，使自动局部调制在 0.9 至 1 间变化，再乘原散射强度；v2 的 0.7 对照保留为历史验收记录。面部中值散射仍为 0.27，鼻型和网格法线不变；粉嫩度使用上表独立参数。

下限 0 可复现旧自动遮罩的强对比，1 表示不压低局部散射；“细节保留”仍可独立关闭。`GeneratedSSSMask` 仅对程序生成的遮罩开启，手工和明确命名的附带遮罩不受自动下限限制。可在“面部散射遮罩”字段指定自己的遮罩和通道。自动定位按标准 MMD 正面轴寻找鼻部，找不到合理区域时保留均匀散射并记录原因；未知模型仍需视觉复核。

## 六档角色几何处理

新字段 `character_geometry_mode` 仅作用于 MMDBridge FBX 的内置 PBR 角色通路：

| 配置值 | 界面选择 |
|---|---|
| `original` | 不添加修改器 |
| `weld_weighted` | 焊接＋加权法向（全部部位，保留原含义） |
| `local_subdivision` | 焊接＋加权法向＋身体及贴身物一级细分（约2倍顶点） |
| `all_subdivision` | 焊接＋加权法向＋全部件一级细分（约5倍顶点） |
| `weld_weighted_except_hair` | 焊接＋加权法向，头发不添加修改器（保留旧含义） |
| `weld_weighted_no_hair_weld` | 焊接＋加权法向，头发仅加权法向、不焊接（新任务默认） |

2026-10-26 新增第五档：按有效 PBR 材质类型识别头发，在原材质部件上跳过焊接和加权法向，保留头发原有几何、法线、蒙皮和全部表情。其它部位继续使用原来的焊接＋加权法向处理。此选择不按角色名或固定槽号特判；手动材质类型覆盖参与识别与缓存。原四档和旧任务的几何含义不变，显式保存的旧选择不会自动迁移。

2026-10-27 按用户要求新增第六档并设为新任务默认：头发只使用加权法向，按面面积、权重 50、保留锐边，不添加焊接；其它部位仍使用焊接＋加权法向。头发沿用原顶点、面、UV、材质槽、蒙皮和全部形态键，只将该部件的加权法向写回导出副本。头发识别仍依据有效 PBR 类型；旧第五档继续保留，不把已保存的“头发不添加修改器”任务重新解释为加权法向。新旧模式具有不同缓存签名，切换后需要新任务重新导出。

六档均支持已确认共面贴层（例如带Alpha的Logo）外移0.1毫米；该步骤不添加修改器。通过共面三角面、蒙皮和全部形态键检查后，仅修改导出副本的贴层位置，保留RGB、Alpha、UV及原材质槽。非共面或关系不明确的部件不统一膨胀，失败原因写入待复核回执。

“头发不添加修改器”档在共用法线处理函数中保留头发的原始法线编码和锐边标记，避免 Blender 整网格法线写回时重新量化未修改的头发角点。导出前逐角点校验，误差超过 `1e-6` 则停止并保留诊断。新默认的“头发仅加权法向”档会计算头发法线，不承诺原法线数值不变；原四档的处理范围保持原样。

第一档不添加焊接、加权法向或细分修改器，除上述贴层外移外保留输入几何与法线，正常保留骨架、表情及必需的导出转换。第二档在贴层外移后沿用保形态键的焊接计算和法线回传，实际导出拓扑不变。两个细分档固定一级 Catmull-Clark，保护原有边界与尖锐部位，贴层跟随同一宿主曲面并保持间距；细分结果真实写入导出副本，加权法向随后计算。焊接距离为0.1毫米，加权方式为面面积、权重50、保留锐边。

局部约2倍、全部件约5倍，是基于已测样本的整个人物Blender／FBX顶点参考估算，不是保证值；实际增长量取决于原始拓扑及选中范围。`character_geometry.counts` 记录处理前后的顶点、面、三角面及逐部件数量和实际比例；FBX回读与UE渲染顶点数需分别查看对应回执。UE会在导入／构建时拆分渲染顶点，增长量可能明显超过估算：本轮GenZ全部件一级为364,937个Blender／FBX顶点，UE LOD0实际为890,841个渲染顶点。此处只记录实测差异，不把原始顶点倍数当作UE开销倍数。

局部档包含身体、面部、脖子、独立嘴唇及全身贴身软层（丝袜、紧身上衣／裤、手套和贴身带状部件）；贴层须验证宿主、蒙皮和全部形态键后随宿主处理。部件名称、物理材质、骨骼及空间证据共同决定自动选择。眼层、眉睫、口腔、牙齿、指甲、头发、鞋、硬件和宽松悬挂部件不自动纳入。

点击开始后，局部档先进行纯PMX预检，外部工具尚未启动。仅在嘴唇、脖子或面部未单独识别时触发“局部一级细分 · 补选部件”弹窗，展示全部原材质槽，疑问项和日志均为黄色。用户可勾选或取消部件，点击“按当前选择继续”后持久化到现有 `character_geometry_overrides` 并自动继续；在这个完整列表中未勾选的疑问项明确记为排除。取消则取消任务；退出后待选择报告保留，恢复任务可继续补选。无界面入口在相同条件下停在 `awaiting_geometry_selection`，可通过 `Controller.confirm_geometry_selection({模型SHA256: [原槽索引, ...]})` 提交完整选择。

没有独立嘴唇、脖子或面部槽时，提示“未单独识别，可能与其它槽合并”，不直接宣称模型缺失。其它匿名槽、衣物、附件等未识别项只记录黄色日志并静默继续，不单独触发弹窗；用户仍可从材质分析窗口主动调整。此规则按2026-10-20的最新要求执行，替代此前“脖子／嘴唇只日志、其它疑问弹窗”的方案。物理材质选择及“应用材质到UE”不会替用户更改几何。

旧任务缺少新字段或其值为 `null` 时，继续使用原解释器、选择范围和缓存签名。旧配置用于新任务时，不能准确对应新范围的局部配置要求重新选择。内置 PBR 六档的新任务使用 v5 几何处理契约：按原 PMX 身份读取补选和材质类型覆盖，同时记录实际导入的修复副本身份。贴层检测输入、覆盖及实际映射继续纳入缓存校验；已有 v4 任务保持原解释与恢复规则。原任务的补选未作用到修复副本时，需要新建任务重新导出，不能通过恢复旧检查点改变网格。此前头发侧面法线优化已归为废案，本功能不恢复该实验；全部件细分的侧面高光／阴影风险仍须按画面判断。

六档原生回归入口为 `scripts/validate_geometry_modes_blender.py`；2026-10-27 的 Blender 5.2.2 夹具覆盖六档、头发原始法线与仅加权法向，以及共面 Alpha 贴层，共 14 组通过。两个本地角色的旧阶段验收证据保存到 `work/character_pbr_20261020/GeometryModes_v1`，不将旧模型证据扩大为新档的角色画面验收。

四档共用贴层外移的追加验收位于 `work/character_pbr_20261020/LogoAllModes_v1`：288项回归、赛车Miku四档Blender／FBX／UE导入及独立重载通过；另有GenZ前两档的Blender叠层回归。14张原生1440p图包含四档静止／动作及前两档外移前后，Logo专项画面通过。其它细分外观风险保持原记录。

## 修改与保存

窗口中的文件字段留空表示使用自动来源。显式指定文件后，选择 RGB 或单独的 R/G/B/A 通道，必要时反转。法线、粗糙度、金属度、透明与方向图使用数据颜色空间，基础色、MatCap 和自发光颜色按颜色贴图处理。

每个模型的覆盖按 PMX 内容哈希和材质槽索引保存，并随任务及软件路径配置保留。更换为内容不同的模型不会套用旧模型的槽位覆盖。

导入之后，在 UE 中选中对应角色，可从窗口点击“应用当前材质到UE”。操作创建新的材质版本，只替换当前选中角色的匹配槽位；“撤销上次UE材质应用”恢复上次绑定。原共享材质保留，遇到后续人工编辑时停止覆盖。新增透明遮罩后，实时应用时需明确选择镂空或半透明；重新生成角色可以重新按 UV 自动分析。

原任务目录较深、修订路径无法保留可靠资产名时，新修订使用同一顶层内容命名空间内的较短目录，并按来源和归属隔离。已有资产和撤销记录仍按原路径核对。

## 白模与兼容

关键贴图缺失、损坏，或材质设置不能转换、UE 编译失败时，对应槽位使用白模，并在诊断中记录原因。可确定的透明遮罩和原始隐藏状态会保留，其它材质继续处理。

仅缺原PMX的Sphere／MatCap效果贴图时，保留可用的基础色和PBR表面，状态为`needs_review`；诊断中的`missing_effects`记录原引用及回退方式。MatCap选择仍是“跟随原PMX”，并记录源模型请求了该效果但资源不可用，不绑定替代图。缺少基础贴图、无效的手动绑定及编译失败仍使用白模。配置窗口的槽位列表区分“缺效果图，待复核”和“缺图白模”；缓存复用也保留缺效果图诊断。

材质由程序在目标工程生成，支持编辑母材质和实例。无需复制测试工程中的手工材质，不依赖运行时 AI。当前目标为 UE 5.8、桌面 DX12/SM6、Lumen 与现有 Substrate Blendable 配置。

## 验证入口

纯规则和界面回归与原生 DCC 验证分开记录。`scripts/validate_geometry_modes_blender.py` 是六档小夹具；真实模型使用 `scripts/validate_character_pbr_blender.py --geometry-mode original|weld_weighted|local_subdivision|all_subdivision|weld_weighted_except_hair|weld_weighted_no_hair_weld`，每次选择一个值和独立输出目录。六档参数不能与旧 `--mesh-finish` / `--contour-*` 实验参数混用。

局部档在启动 Blender 原生准备前检查嘴唇、脖子和面部；无界面入口出现 `awaiting_geometry_selection` 时，读取报告并提供明确覆盖后再运行。不能跳过选择或把验收夹具中的已审核槽位假称为用户本轮选择。

UE 侧还需真实导入、材质编译、槽位绑定、独立进程重载、表情/骨骼及同机位画面对照。`scripts/validate_character_pbr_ue.py` 和对应批次夹具提供专用入口，不把脚本存在当作任意素材均已通过。源码安装检查、测试与原生入口的职责见 [架构](ARCHITECTURE.md#验证和打包)。
