# 场景材质自动烘焙兜底与分阶段验收

`Settings.material_bake_fallback` 默认为 `True`，`material_complex_strategy` 默认为 `pbr_bake`。GUI 默认启用“材质转换失败或超时时允许烘焙贴图兜底”。缺字段的旧配置使用新默认值；旧配置显式保存的关闭开关或 `nodes` 仍保持原选择。强制材质策略 `nodes` 禁止烘焙。

转换从源渲染器有效输出出发，递归展开节点组，并保留组实例输入参数、嵌套依赖、静音旁路和有效混合分支。未连接节点、未使用的组输出及可证明不生效的 Mix 分支不会触发烘焙。是否可靠按节点操作、参数和依赖判定，不使用节点数量、组名或材质名阈值。

先走可靠的节点／局部字段转换；局部失败仍先升级到受影响的通道。未恢复的转换异常、未知表面、转换超时和实际 UE 完整材质编译失败进入整套 PBR 贴图兜底。`material_conversion_timeout` 默认 120 秒，可在 GUI 调整，0 表示不限时。预算覆盖每次单材质转换，遍历节点和闭包及完成转换时检查；这是协作式超时，不能强行中断正在执行的 Blender 原生烘焙或 UE 原生编译调用，原生调用返回后才判断超时。整套兜底烘焙不使用这项转换预算，避免重复进入兜底。UE 的节点创建／连接、未知表达式／闭包、缺少 Substrate、编译失败和转换超时回退须匹配当前运行时代码哈希和实际失败材质身份，先归档旧清单与失败回执，每个源材质最多自动尝试一次；旧版本的错误先重新验证，不直接强制烘焙。资产保护、保存失败和用户停止不会被当作材质图转换失败来重试。

基础色通过无光照的字段输出烘焙，不包含灯光和阴影；基础 PBR 保留 UE 实时光照响应。Mix Shader 的透明覆盖率与有覆盖部分的颜色分别求值。多 BSDF 压缩为一个 PBR 只保留这些通道，分层高光和法线可能近似，活跃的清漆、透射、次表面等额外效果记录为剩余限制。Add Shader、彩色透明和不能静态求值的效果不宣称可等价烘焙。

整套兜底统一写出基础色、金属度、粗糙度、切线空间法线、透明度和自发光六张贴图，包括值恒定的通道。法线使用原生 Normal bake；平坦法线的贴图编码为约 `(0.5,0.5,1)`。基础色使用 sRGB，金属度／粗糙度／透明度／法线使用 Non-Color，自发光使用线性 EXR 保留 HDR。UE 跳过可选场景母材质，直接把贴图连接到对应 PBR 输入。其它节点和混合策略继续保留常量优化。共享贴图还须确认字段语义、参数、源资源、UV 布局、几何及材质面覆盖一致。世界坐标／实例依赖把相关变换与随机身份加入缓存键，资源路径也包含完整上下文身份，避免不兼容结果相互覆盖。

`fallback_attempts` 记录失败节点、输出、组路径、原始原因、尝试范围、耗时、结果及图像身份。`baked_fields` 保留语义签名、数据域、插槽类型和源 UV 依赖。烘焙成功仍标记 `needs_review`。视角、光线、未知动态依赖不会静态缓存；导数相关法线须使用原生 Normal 通路，组内独立闭包法线不能用整表面法线替代。未知 Shader/体积不能伪装为普通 PBR。

材质分析修订号为 17。烘焙兜底开关、复杂材质策略及转换预算不改变冻结几何身份，但改变设置或材质语义会归档旧材质分析与 Payload，重新分析材质。纹理复用还须通过节点、图像版本、UV、几何、对象/实例上下文、帧及分辨率的缓存身份验证。GUI 的“按当前策略重做材质”先归档旧任务清单、导入报告和全部参考图，再重新导出材质并复用冻结几何；转换或参考渲染尚未退出时禁止调用。

依赖 Generated 坐标的材质在完整求值网格上先保存原始纹理空间，再执行空间分块。坐标由两层专用 UV 承载，BMesh 切割新增顶点时插值这些坐标；分块材质分析直接复用，不再要求分块顶点数与完整源模型一致。此流程同时供节点转换和 PBR 烘焙使用，不要求开启外观还原。依赖分析在单次导出中按源材质缓存，避免同一材质在每块重复展开。源模型本身拓扑不兼容时仍保留错误，不能用分块边界伪造 Generated。

恢复旧冻结网格时检查 Generated 载体。旧的自动分块若依赖 Generated 但缺少坐标，明确要求保留旧任务并新建场景任务；仅重做材质不能补回丢失的原始对应关系。检查在归档材质分析之前完成，保护旧清单与断点。已经明确记录不支持拓扑的部分失败仍可恢复，其失败状态继续保留。修复不会热更新正在运行的 Blender 进程。

## 现有策略清单

| 策略 | 条件／设置 | 输出和取舍 |
| --- | --- | --- |
| 自动选择 | `material_strategy=auto`，默认 | 简单 PBR 优先节点；复杂材质根据有效图和几何选择节点、局部烘焙或混合流程。 |
| 强制节点 | `nodes` | 生成 UE 节点与材质函数；不允许烘焙，无法转换时记录失败。 |
| 混合还原 | `hybrid` | 支持的字段生成节点，不兼容的静态程序字段烘焙成贴图；局部失败可升级为通道烘焙。 |
| 显式烘焙 | `bake`（对象属性也兼容 `baked`） | 现有按通道烘焙模式，仍可能保留可转换表达式及特殊表面处理；与整套 PBR 兜底独立。 |
| 大面积平铺 | 自动 `tiled` 或对象覆盖 | 使用混合／世界投影，避免整块低密度贴图；需视觉复核。 |
| 大型立体分块 | 自动 `chunked` 或对象覆盖，且满足分块条件 | 分块生成独立烘焙 UV 和贴图，复用后续材质流程。 |
| Shader 闭包还原 | 启用外观还原，存在有效多 BSDF 混合 | 保留混合树，使用 UE Substrate；程序字段局部烘焙。玻璃、水、薄片透光走专项处理。 |
| 场景母材质复用 | 启用 `use_scene_master_material`，表达式满足接口条件 | 建立母材质实例并填参数；完整 PBR 兜底跳过此路径。 |
| 角色专用 | PMX／MMD 角色 | 使用角色／眼睛母材质、Toon／Sphere 贴图；与本次场景 PBR 自动兜底独立。 |
| PBR 贴图兜底 | 默认启用；未恢复的转换异常或预算超时、UE 节点转换／编译失败 | 从源 Shader 烘焙六张贴图，直接连接 PBR；删除复杂闭包及特殊遮罩，保留原因与 `needs_review`。 |
| 最终占位／失败报告 | 不支持的 Shader、动态依赖或烘焙仍失败 | 记录烘焙失败，调用者继续独立对象并保留占位／跳过报告；不得视为已还原。 |

匿名 Blender 原生回归：

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --disable-autoexec --python scripts\blender_material_fallback_regression.py
```

`scripts/run_scene_stage_gui_acceptance.py` 创建可见的原开发 GUI，使用真实按钮信号安装桥接、导入场景、渲染参考帧和生成对照。每次 `--stage 1/2/3` 只完成指定场景，不自动进入下一场景；使用不同 `--revision` 保存每次证据。`--reference-from` 只能复用哈希、源文件身份、相机和帧一致的 Blender 参考图。调度器没有固定总时限；失败进入 attention 状态，保留进程回执和断点。

保存/重开证据由 `scripts/ue_scene_stage_audit.py` 在实际 UE 进程采集。重开后等待 USD 组件计数稳定，记录材质、网格、实例、Stage 根层及资源加载；计数变化不会仅因随后渲染成功而视为通过。

重开审计从导出 Prim 查询 USD 生成组件，逐个加载任务引用的 UE 资源包。资源重载成功与几何计数一致是独立结论；退化面清理等数量差异保留 `geometry_status=needs_review`。真实编译失败材质按 ID 和完整资源路径匹配，名称／路径前缀碰撞不能选中无关材质。恢复测试覆盖旧运行时错误重验、匹配终态回执、子进程结束及同源材质最多一次自动重试。

调度器兼容历史字符串和当前 `root_layer` 字典形式的 USD 清单。进程返回零时仍检查最终清单及文件；完整的灯光／环境场景可以没有网格。导出清单写完不代表子进程已退出，后续导出或 UE 导入须等待当前导出进程退出。缺失文件和未完成清单保持失败，不能用成功状态覆盖。

本轮阶段顺序为涂鸦墙、cherry、MyGO。第一阶段保留原始基线和回滚记录；阶段报告交付后等待用户验收，后两场景保持暂停。所有共用修复须回归其影响到的前序场景。

重复参考渲染使用含配置摘要的独立 MRQ 预设，保存后登记保护哈希。旧版未登记预设保留，不冒充用户资产获得覆盖权限。
