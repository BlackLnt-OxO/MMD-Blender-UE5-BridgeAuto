# 世界雾默认方案与实验性异质体积

2026-10-11 用户指定 `/Game/NativeFogValidation_20261008_224113` 的原生雾版本作为新导入默认。正式入口采用 `native_balanced`：8 像素栅格、128 深度层及 `r.VolumetricFog.InjectRaytracedLights=1`。复用该版本的静态源 SVT 密度／边界、Volume 域代理和高度雾载体；视口、参考帧和独立渲染恢复相同的原生绑定。SVT 是数据，实验性标注指 Heterogeneous Volume 渲染路径。

默认开销复核：`work/native_fog_default_gui_20261011/receipt.json`。港口、RTX 4060 Laptop 8 GiB、UE 5.8.2、1280×540、1×1 采样；无体积雾／原生雾无光追注入／原生雾有光追注入分别正反顺序各跑一次，共 180 张实际输出帧，排除每轮前 16 个 GPU 样本。三种整帧 GPU 中位数为 40.37／41.40／44.27 ms；`GPU/VolumetricFog` 为 0／0.741／3.243 ms。每帧读取雾场及散射积分的基础成本较低，实时光追遮挡注入是较大的额外成本，约增加 2.502 ms 的雾 GPU 耗时，整帧约增加 6.94%。因此按用户要求保留当前默认过程，不新增单独开关；GUI 明确原生 Lumen 默认、实时照明及路径追踪源雾基准，操作按钮分行防止横向裁切。857 个受保护资产不变，71 项相关测试通过。2560×1080 无雾基线因专用显存超过 90% 被保护停止，以上低分辨率测量不能证明高分辨率稳定性，不能把港口显存压力仅归因于雾。

原生雾能产生物体遮挡后的雾中暗带，但不会自动模拟玻璃透镜折射聚光。源灯光的阴影和体积贡献仍保留；软件兼容配置不强制开启硬件光追。彩色消光取均值、共享相函数、静态帧及细结构近似仍保留 `needs_review`。不支持的源数据保留异质体积并报告限制，不丢弃雾。默认选择不等于完整港口画质／稳定性验收通过。

现有任务、原生实验地图和源渲染预设不自动迁移。新导入准备原生代理，同时保留源异质体积载体供路径追踪使用；两种渲染入口验证实际绑定，缺少代理时要求重新导入，不仅切换控制台值。

原生验证地图共用旧源 USD 包时，包内可能没有雾方案字段。视口恢复现在根据地图中保存的原生代理绑定选择 `native_balanced`，启用光追灯注入并保持源 SVT 驻留；包内已有明确选择时仍保留该选择。此前仅 MRQ 指定了原生方案，视口会退回 `legacy`，缺少雾中光追阴影。

视口菜单切到路径追踪时必须恢复原始 SVT 异质体积，并隐藏原生代理及高度雾载体。此前根据后处理体积的 Lumen 设置判断管线，无法识别视口菜单变化，导致源雾仍隐藏；这会同时丢失灯塔和路灯的彩色雾光。编辑器专用 `MMDBridgeViewport` 模块读取实际视口模式，模式变化后重新恢复绑定；不改原始密度、RGB 消光、相函数或灯光参数。独立渲染继续按实际 MRQ 通道选择源雾。UE 5.8 的路径追踪使用共享开关 `r.HeterogeneousVolumes`，没有 `r.PathTracing.HeterogeneousVolumes` 这个开关。

视口接口的预编译模块只在与所选 UE 的 BuildId 一致时安装。更换引擎后需重编译，不能复制不兼容 DLL；未安装接口时手工菜单切换不保证自动恢复源雾。绑定是世界级状态，同一世界同时打开不同渲染模式的视口尚不支持。路径追踪保留为外观基准，原生 Lumen 的浓度、彩色吸收和遮挡近似仍需独立视觉验收。

修复验证存于 `work/native_fog_pt_baseline_20261011/repair_receipt.json`：UE 5.8.2 D3D12 编辑器实际切换 Lit → Path Tracing → Lit，原始两份体积与原生代理可见性均正确。原地图与修复地图各渲染道路、灯塔两机位，共 4 张 1280×540、64 采样路径追踪帧；相机、原始体积及材质匹配，测试仅在临时渲染世界隐藏用户挡板。道路左侧雾区的平均 RGB 每通道差小于 0.02/255；整图平均绝对差分别为道路 0.970/255、灯塔 0.085/255。857 个受保护资产哈希不变，86 项相关测试通过。这是恢复原 UE 路径追踪基准的证据，不是新的 Blender 等价性或 2560×1080 高采样稳定性验收。

2026-10-11 挡板对照进一步发现：Lumen 的体积间接照明会填充暗区，挡板增加后部分雾反而变亮；临时关闭 `r.Lumen.TranslucencyVolume.Enable` 后该贡献消失。这是诊断设置，不作为默认。当前保留 8 像素／128 层，验证地图约 1732 m 的采样距离，以及 Lumen 32 像素的间接照明网格，细雾影和玻璃光学传播仍未通过视觉验收。不能把注入开关修复等同于完整遮挡效果验收。

## 新性能记录

UE 5.8.2、RTX 4060 Laptop 8 GiB、1280×720、Lumen；四轮异质体积与四轮普通雾测试，均每轮输出 48 帧。采集实际输出期间 GPU CSV，去掉前 16 个样本，各方案两轮共 70 有效样本。下列数值是 GPUTime 中位数。

| 方案 | 所用雾路径 | GPU 中位数 |
|---|---|---:|
| Cinematic 无缓存 `vsm_nocache` | 可见的均匀异质体积 | 84.57 ms |
| VSM＋精细缓存／步进 `vsm_finer` | 同一可见异质体积 | 33.84 ms |
| 普通雾原行为 | 高度雾／普通体积雾 | 10.04 ms |
| 光追灯注入 `rt_inject` | 同一普通体积雾 | 11.18 ms |

精细缓存相对无缓存约少 60.0% 整帧耗时。普通雾灯注入相对其自身基线约增加 11.4%。普通雾与异质体积的完整光输运和边界表达不同，不能仅凭耗时把任意 VDB 自动替换成普通雾。盒状 froxel 和通用 SVT 适配候选单轮分别 10.49／11.67 ms；只有单轮，且完整画质矩阵未通过，不能成为通用发布依据。

## 低开销方案的通用性

`rt_inject` 对已转换为普通体积雾的源雾有意义；它不直接修复异质体积，也不提供任意 VDB 形状与程序化密度转换。盒状局部 froxel 只证明了静态均匀盒子；旧通用 SVT 边界候选的 5 cm 暗带对比仅 36.57%，未达 60% 门槛。混合相函数、相机／时间相关字段、动画、彩色消光和自发光尚无完整验证。因此没有证据表明其源雾覆盖范围高于两个异质体积补充，主方案保持原样。

普通体积雾的分辨率、相函数及动态时间滤波限制参见 [UE 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-fog-in-unreal-engine)。异质体积的缓存／步进与内存权衡参见 [UE 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/heterogeneous-volumes-in-unreal-engine)。

## 实验补充入口

正式下拉框提供默认 `native_balanced`，以及实验性 `vsm_finer`、`vsm_nocache`、`legacy` 和待验证的 `detail`。旧任务缺失设置时保留 `legacy`；已保存的 `native_quality/native_detail` 按原档位载入，不再改回 VSM。`detail` 的生产验收注册表仍为空。两个 VSM 补充接受 UE 5.8.2、Lumen 和已转换且有源 prim 路径的异质体积。

- `vsm_finer`：LightingCache=2、Scalability=3、VSM；原生组件 StepFactor=0.25、LightingDownsampleFactor=0.5。
- `vsm_nocache`：LightingCache=0、Scalability=3、VSM；保留／恢复源组件步进和缓存倍率。
- 仅工具管理的源灯光切换至 VSM 阴影，其他灯不改；不重写源密度、曝光或材质。
- 视口、参考帧和后台渲染通过源 USD prim 定位体积，拒绝缺失或不唯一的目标。组件参数使用比较后恢复，用户手工修改会撤销该字段的自动控制。
- 实验结果始终为 `needs_review`，小测试不是整场景视觉验收。已有任务不自动迁移。

原生 UE NullRHI 验证了参数切换、回到原值和手工覆盖保留；它是原生属性验证，不是新增画质／性能证据。真实 MRQ 的可见雾及性能证据另存。
