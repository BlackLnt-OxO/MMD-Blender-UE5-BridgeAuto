# 通用雾光遮挡：实验性验证记录

当前交付的是独立测试、验收门槛和默认关闭的实验入口。**尚未发布通过完整画质、性能及场景验证的自动修正配置。选择 `detail` 当前会记录 `limited` 并保持原行为，不代表雾光遮挡已经解决。** 未重新导入港口，也未覆盖原关卡。

## 通用流程与边界

- 设置 `fog_occlusion_quality=legacy/detail` 接入 GUI、任务、导出元数据、视口恢复、MRQ 和后台渲染记录。旧任务缺字段按 `legacy` 处理。
- 主方案的节点/PBR 转换、树叶默认策略、物理灯光、HDR、曝光、雾密度和现有默认控制值保持原样。
- 依据源体积类型、均匀系数证明、单位、时间策略、相函数和边界选择候选；不依据场景名、物体名或港口路径。
- 均匀局部体积可评估普通体积雾的 froxel 路径。盒状原型仅验证盒子；任意闭合边界必须复用原 SVT 遮罩并单独证明一致。缺证明、动画、混合相函数、程序化/视角相关系数、自发光和折射遮挡保持原表达并复核。
- 不用降低密度、增大发光或改变散射方向来制造分数。大范围雾不自动整体加密；分区算法只生成均匀盒子的无重叠规划，尚未接入原生局部细分。

## 小测试与测量

UE 5.8.2、RTX 4060 Laptop 8 GiB；独立 `/Game/FogOcclusion_20261008_190605_bc27` 资源目录。Point/Spot、2/5/10 cm 不透明条和 Masked 镂空，固定相机、曝光及散射参数，关闭景深和 Bloom。普通体积雾与异质体积分别测试；路径追踪 128 spp 是同帧参考。

实时性能测量输出 48 帧，在 MRQ 真正输出帧时开始 GPU CSV，去掉 16 个预热样本后通常有 34–35 个有效 GPU 样本。使用实际 `GPUTime`，不以 CPU FrameTime 或启动总耗时代替。

以下耗时均为小测试结果，不能作为港口性能承诺。表中有数值的画质比较针对同机位的 5 cm Point 遮挡条。

| 候选 | GPU 中位数 | 画质/预算结论 |
|---|---:|---|
| 异质体积原行为 | 30.20 ms | 对照基线 |
| 异质体积 VSM＋中等照明缓存 | 39.94 ms | 已增加约 32%，不作为低成本通用默认 |
| 异质体积 VSM＋细缓存/步进 | 49.74 ms | 开销约增加 65%；恢复细节的候选保留为诊断 |
| 普通体积雾原行为 | 15.84 ms | 独立基线 |
| 普通体积雾光追灯注入 | 16.24 ms | 5 cm 对比为参考的 97.86%，边界误差 0.865 px；不等于全部遮挡类型通过 |
| 有边界的均匀盒状 froxel 原型 | 15.98 ms | 5 cm 对比 99.90%，误差 0.926 px；比异质体积基线快约 47%，但只证明盒状原型 |
| 复用原 SVT 遮罩的通用候选 | 29.23 ms | 5 cm 对比仅 36.57%，低于 60% 门槛，拒绝发布 |

盒状原型中 2 cm Point/Spot 有可测暗带，对比分别约 87%/90%，边界误差小于 2 px。部分普通雾的 Masked 案例在原采样下误差超过 2 px；把 GridPixelSize 降到 2 后，中央暗带误差降至约 1.03/0.87 px，但 GPU 耗时约 28.34/29.09 ms。这个结果不能支持“细采样既通用又低成本”的结论。镂空度量目前只覆盖中央暗带，所有孔洞仍需人工复核。

局部盒状、普通雾和异质体积的基线分开；不把其他机位、其他体积类型的耗时拿来给单个案例发预算合格证。整套候选未同时达到完整矩阵、画质、性能、缓存预算及人工复核要求，`VALIDATED_PROFILES` 保持为空。

## 原因与其他候选

该异质体积小测试表明：关闭照明缓存的 Cinematic 诊断能恢复细节，仅关闭间接照明不能恢复，说明缓存精度是这个测试的瓶颈。不能据此认定所有场景都只有同一个原因。关闭缓存只用于诊断，不进入生产默认。

传统阴影贴图未在这次异质体积测试中带来开销优势。单纯分析型 Local Fog Volume 不能自动替代源雾：阴影支持及密度分布有区别；需要光柱仍应评估体积雾 voxelization。IES/Light Function 可表达灯本身的方向配光，静态烘焙配光可作为以后单独候选，但不能宣称等同于可移动几何的真实雾中遮挡。参考 [普通体积雾文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/volumetric-fog-in-unreal-engine)、[局部雾文档](https://dev.epicgames.com/documentation/unreal-engine/local-fog-volumes-in-unreal-engine?lang=en-US)、[异质体积文档](https://dev.epicgames.com/documentation/unreal-engine/heterogeneous-volumes-in-unreal-engine)。

## 代码与后续门槛

`fog_occlusion.py` 保存类型判断、成本估计、完整矩阵验收、无重叠规划及临时值的比较恢复。`ue_fog_occlusion.py` 是共享配置边界。`ue_fog_froxel.py` 是**未启用的原生候选**：显式准备隐藏辅助对象，在加载副本中复用源 SVT；不从普通转换入口调用。相关 `scripts/*fog*` 保留可重复的原生测试及失败收据。

未通过验收时保留 legacy 并报告限制。导入成功、渲染成功和雾光画质通过分别记录。小测试通过后才能安排现有港口的临时运行副本 A/B；那一步也通过后才讨论新的完整导入。

校验记录在 `work/fog_occlusion/20261008/summary.json`：1105 个源文件及已验收资源、受保护主方案模块和原有 Lumen/Volume 控制值均未改变。71 项相关测试通过，覆盖旧任务设置、主方案回归、GUI、临时控制值与渲染记录。独立测试曾暴露 USD 缓存重载及空材质绑定问题，失败运行没有计入有效结果；原生 SVT 收据成功之后仍因对比度不足而拒绝候选。没有把技术渲染成功当作画质通过。
