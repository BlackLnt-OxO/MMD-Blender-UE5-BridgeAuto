# 场景还原 GUI 与管线边界

新导入默认启用场景光影还原、Lumen 和 `native_balanced` 原生体积雾：读取源静态雾场，实时计算光追遮挡注入和散射；路径追踪使用原始体积，保持现有还原基准。当前默认 8 像素／128 深度层，港口两轮实测注入额外约 2.5 ms，整帧增加约 7%，因此不增加单独开关。界面“场景还原”页说明此默认过程和基准，已有策略选择保留；操作按钮按三列分行，避免控件横向挤出窗口。性能回执与 GUI 截图位于 `work/native_fog_default_gui_20261011/`；原生雾近似和高分辨率显存限制见 `world_fog_supplements_20261008.md`。

现有世界光、灯光、体积雾、色彩和材质转换实现标注为**路径追踪还原基线**，保留代码与既有任务。两条管线共用几何、UV、材质转换、烘焙贴图、VDB 和 HDR 环境资产，只调整 UE 光照、雾照明、半透明反射及渲染设置；路径追踪画面不作为 Lumen 验收依据。

新场景任务统一放入 `/Game/Scenes`，子目录为源文件名加两位递增编号，不添加 `A_`、`Scene_` 或哈希前缀／后缀。例如 `railway.blend` 导入为 `/Game/Scenes/railway_01`，`港口.blend` 为 `/Game/Scenes/港口_01`；保留中文，UE 不允许的字符转换为下划线。已选择工程时编号在该工程中预留，已有同名目录（包括用户目录）使用 `_02` 等后续编号。USD、材质、雾、地图和序列共用同一目录。旧任务恢复时保留原资产路径。

新任务载入旧配置中的 `On_9_24_开发_PlanV2/On_9_25/On_9_26` 默认目录时，统一使用 `/Game/Scenes`。导入及重开受管理关卡时，`ShowFlag.PathTracing` 使用默认值 `2`，视口菜单可自由选择实时渲染或路径追踪；手工覆盖仍保留。明确选择渲染管线的 MRQ 任务在自身渲染期间使用对应的 `0`／`1`，结束后恢复原值。

USD 恢复导入先校验源文件，再复用哈希相同的已部署文件，避免重复覆盖 UE 正在读取的几何 Payload。USD 场景几何失败时任务标为 `failed`，保留导出包与资产，不能将仅有环境和相机的地图报告为导入完成或仅需外观复核。

`场景还原` 页集中显示光影还原开关、Lumen／路径追踪选择、灯光倍率、雾密度、曝光、体素精度和世界雾范围。材质策略、烘焙分辨率和其他转换参数保留在参数页，通过“打开材质与其他参数”进入。材质转换运行时无需 AI。

“世界雾渲染方案”新导入默认采用原生体积雾 `native_balanced`，对应 `/Game/NativeFogValidation_20261008_224113` 的 8 像素／128 深度层版本，并启用光追灯注入。静态源 SVT 继续保存密度与边界；原生雾负责 Lumen 受光和遮挡。它不自动模拟透镜折射聚光，彩色消光、共享相函数及细结构仍需复核。VSM＋精细缓存／步进、Cinematic 无缓存及源异质体积均标注为实验性；已有任务保留原配置，缺少原生代理时需重新导入。路径追踪恢复源体积载体；不支持的源数据保留原表达并报告限制。详见 [验证与范围](world_fog_supplements_20261008.md)。

完成转换后可在该页读取已有任务、生成 Blender／UE 参考帧和对照，分别查看两张参考图，并复制所选管线的完整 MRQ 配置路径。资产区显示实际关卡、序列和配置；最新参考帧区按回执显示图片的实际管线与源镜头，不随管线下拉框改变旧图片的标识。查看还原报告同时显示 UE 导入报告、参考帧回执和差分结果。

光影参数用于下一次场景转换，修改后需重新导入；选择已有任务后直接切换渲染管线复用原资产，不把新倍率悄悄写入旧任务。载入配置或任务时保留记录的软件路径，即使路径尚未出现在检测列表中；后台操作开始时立即禁止切换任务或开始新导入。

新对照记录两张参考帧的哈希；更新参考帧后查看旧对照会提示重新生成。UE 渲染图有成功回执哈希时按哈希核对，拒绝把失败渲染或不匹配图片当成当前结果。历史 Lumen 回执未验证关闭路径追踪时，界面明确标注其管线尚未确认。

新任务默认 Lumen；未保存 `scene_render_pipeline` 的历史任务载入时按路径追踪基线处理。选择已有任务后可直接切换管线再渲染，复用同一导出包、同一 UE 关卡与资产，无需重新导出或烘焙；参考帧请求携带管线选择，保留原任务配置。UE 回执记录实际 MRQ 渲染 Pass、所选管线及运行时 GI／反射设置，避免混淆图片。改动源场景或烘焙参数时仍需重新转换。

Lumen 使用延迟渲染、Lumen GI 与反射；路径追踪使用独立 Path Tracer Pass。两者都使用源活动相机、参考帧、画幅和源色彩配置。参考帧生成成功仅表示渲染完成，差分指标始终保留 `needs_review`。

参考帧的完整配置保存为同一资产目录下的 `Materials/MRQ_Lumen` 或 `Materials/MRQ_PathTracing`，可直接在 UE 手动渲染中加载；`MRQ_SourceLook` 保留为共用基础配置。Lumen 的完整配置明确设置 `ShowFlag.PathTracing=0`，路径追踪配置设置为 `1`；回执同时检查运行时开关、全部渲染 Pass 并记录输出图片哈希。仅有延迟 Pass 的名称和 GI 参数不足以排除全局 ShowFlag 对实际渲染的覆盖。

完整还原需要 Blender 5.2 及内置 OpenVDB／OpenColorIO，UE 工程需要 USDImporter、OpenColorIO、MovieRenderPipeline 和 MMDBridge。安装或更新桥接后重启 UE；运行时桥接哈希与磁盘版本分别检查。UE 当前关卡未保存或渲染队列已有任务时明确提示处理，保留用户内容和队列。

渲染默认关闭显存保护，仍记录专用、共享及进程 DXGI 内存。导入／导出保留原有显存保护；导入还保留额外 5% 预算。停止之后等待运行进程或 UE 回执结束再启动下一项。

重开工具管理的 USD 关卡时，视口恢复与 MRQ 共用的体积渲染参数；离开该关卡时恢复项目原值。此前这些参数仅在导入及 MRQ 时应用，重开编辑器后的视口可能与渲染帧不同。更新此修正后需安装桥接并重启 UE；桥接版本检查包含环境和体积模块。

设置分布：关卡内 `Source render look` 后期体积保存 Lumen GI、反射、高质量半透明反射、手动曝光和 Bloom；雾参数保存在雾 Actor 和体积材质中；完整 MRQ 配置的 `Color Output` 使用 `OCIO_Blender` 的 `Scene Linear → Blender Display`，替代 UE Tone Curve，`Console Variables` 保存体积开关和管线开关。只把 `LS_MMD` 加入 MRQ 不会自动加载这些输出设置。

视口 OCIO 是每个视口独立的显示设置，不存储在后期处理体积里。桥接按关卡和活动视口共同缓存恢复状态，切换视口时重新应用源色彩；无活动关卡视口时等待。核对画面时使用同一关卡、源相机和序列帧，视口 `Lit`、实时、曝光 `Game Settings`，并在视口 OpenColorIO 菜单确认同一转换。MRQ 默认质量覆盖和预热仍可能造成差异，实际视口一致性需要另外验收。

Lumen 管线的视口和 MRQ 共用画质设置：启用 Lumen 体积间接照明，异质体积最长 1024 步、1024 阴影图、32 位阴影精度，均匀体积雾使用 4 像素栅格和 128 深度层。Lumen 场景照明、Final Gather 和反射质量均为 2；源环境强度、雾密度、相机与材质不因此改动。离开工具管理关卡恢复原控制台值，路径追踪基线继续使用原设置。渲染回执记录实际体积控制台值，UE 报告的 `assets.render_presets` 保存两条完整配置路径。光照与雾仍有实时近似，视觉状态保留 `needs_review`。

GUI 自动参考帧在临时 PIE 世界恢复导出包中的源相机光学参数，并记录实际焦距、光圈、焦点模式和距离；不覆盖编辑器中的相机调整。手动 MRQ 使用当前序列相机。对比两种入口时，须核对镜头参数，避免将失焦差异归因于光照或雾。

玻璃通用修正保留源 Glass BSDF 对反射和透射的颜色作用，并保留背面：闭合灰玻璃的窗后内容不再因少一次透射衰减而过亮。所有透光表面使用 Surface Forward Shading；Lumen 在工具管理的后期体积中启用高质量半透明反射。该设置覆盖最前层半透明表面，多层仍受 Lumen 机制限制，见 [UE 官方说明](https://dev.epicgames.com/documentation/unreal-engine/lumen-global-illumination-and-reflections-in-unreal-engine)。镜头被前方透明板遮挡造成的屏幕折射问题按用户要求排除本轮验收。

按钮检查覆盖信号连接、配置保存／载入、场景独立预检、三类导入入口、参考帧与对照、报告、旧 FBX 命令、桥接、CameraCutAuto 帧编辑、PhysicsBakeFix 文件输出及 MMM Runtime／插件文件操作。新参考帧入口另以真实 Blender 和 UE 验证；角色烘焙和人工导出窗口的整套外部流程未因本次 GUI 检查重新验收。

开发版启动：`.venv\Scripts\python.exe scripts\desktop_entry.py`。本次不替换历史验收 EXE。

世界环境导出自动处理嵌套节点组的实例输入。HDR 烘焙与诊断分别记录：诊断失败保留已验证尺寸、有限像素及哈希的有效 HDR。依赖 Light Path 的世界另存相机背景与冻结 diffuse/reflection 上下文的照明 HDR；背景用于现有背景流程，照明用于天空光。多天空、独立反射或其他射线分支仍需视觉复核。

灯光颜色与强度可通过 Blender 原生求值解析静态简单计算、色温和节点组。无法表示为常量的字段仅支持明确的标量 Incoming 角度表达式或外部 IES，分别生成受工具管理的 Light Function 和 TextureLightProfile。彩色角度分布、组合 IES、方向性幂运算和可能除零的表达式保留诊断，不能视为可靠还原。IES Strength 只计入光源能量一次；UE 使用源功率换算后的强度，不另外启用 IES 亮度。

多个散射相函数不再导致整个世界雾跳过。导出保留各闭包的密度、颜色、吸收、发光、相函数和混合权重描述，并以总消光、散射及散射加权 HG 一阶矩生成有限范围 VDB。只在此前拒绝的混合相函数世界雾中启用此近似；默认源相机周围 100 米、256 体素精度。Camera Ray 与相机坐标冻结于参考帧，Generated 使用有限采样范围，因此其他视角不保证等价。当前 UE 5.8 Lumen 异质体积实际使用各向同性散射；连接 Phase G 或云材质双 HG 节点不代表此渲染路径支持该相函数。报告保留源分量、导出模型与运行时模型，并标记 `needs_review`。

已导入但需要视觉复核的世界项记录在 `checks.appearance_visual_review`，与实际未导入项分开。以上更新不修改表面材质 `legacy_main_v1`、树叶默认 `legacy_diffusion`、水材质和占位材质补修策略，也不自动迁移已有场景。此前失败的世界环境或雾现在成功导入后会改变光照和画面，需要对照验收。
# 选中物体的材质表面逻辑

在 UE 中选中网格物体，点击“场景还原”页的“分析／切换 UE 选中物体的材质…”。无需选择转换任务，也无需回到原导入关卡。工具实时读取当前材质模式、双面、遮罩与折射连接；沿材质资源目录读取 `.mmd_bridge_namespace.json`，再核对工程、场景、来源材质 ID 和任务资源绑定，自动定位 Blender 转换记录。重建前再次验证冻结输入文件。

勾选要修改的材质槽，再选择镂空遮罩、不透明、薄片透光＋镂空或透射折射。来源缺失、记录冲突或被手工复制后无法对应的材质仍可查看 UE 状态，但不能提交重建。多个工程连接时使用 GUI 中选定的目标工程；每次应用仅支持同一转换场景、同一种绑定通路中的槽位。

这里切换的是表面行为，不是节点／混合／完整烘焙策略。工具读取已导出的材质记录，生成独立候选材质。USD 生成物体通过独立 USD 层绑定；已经放到其他关卡的独立网格体使用当前关卡实例的材质覆盖，并保存当前关卡，保持网格资源和源 USD 不变。共享母材质保留。切换／撤销前请保存手工改动。USD 绑定失败恢复原根层；独立组件绑定失败恢复原槽位。“撤销上次材质逻辑切换”无需选择任务，自动使用最近操作的来源任务；关卡不匹配或目标槽已有后续编辑时阻止覆盖。

镂空优先使用源 Alpha；没有有效 Alpha 时，仅接受唯一的已导出 Opacity 贴图。缺少遮罩、角色材质、未知源材质或无法唯一匹配的 USD 子集会报告原因，不提交绑定。合并散件的单个实例、未经本工具导入的 UE 材质目前不属于此功能的验证范围。使用更新后的源 GUI，并在部署桥接后重启 UE。

新导入增加了保守的植物图集修正：同系列 Albedo／Opacity／Translucency、黑色发光下误接的 Opacity、开放薄片几何和简单 Principled 表面必须同时成立。修正独立裁切，透光使用现有薄叶散射配置；不把所有薄片或所有 Transmission 材质改成植物。已有场景需要手动切换或重新转换，更新代码不会自动改动已有绑定。
