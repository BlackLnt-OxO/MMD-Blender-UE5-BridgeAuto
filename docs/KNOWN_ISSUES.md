# 已知问题

本页列出当前版本的兼容性与转换限制。

## 玻璃与半透明

部分 Substrate 玻璃在 Ray Traced 半透明、包含光追折射时出现黑玻璃，多层与立体交界也可能异常；目前没有适用于所有场景的统一修复。

切换为“透射折射”不能解决上述渲染器问题。同一视图的 Raster／Ray Traced 半透明方法受全局后处理配置控制，不支持按物体分别切换该方法。

## 跨渲染器差异

不支持的节点、介质及视角／时间相关效果会近似转换或标记需复核。场景按参考帧导出，不完整迁移 Blender 动画、模拟或第三方效果。缺失源贴图与缓存应先在 Blender 修复。

原生雾不计算玻璃透镜折射后的聚光；彩色消光、多介质和细结构需要比较。一个世界同时打开 Lumen 和 PT 视口时，雾可见性不能独立维持两套状态，先用一个活动视口检查。

## 角色材质和描边

显式选择官方卡通需要 Toon API、Substrate 和 Blendable GBuffer，条件不满足会停止，不静默改成 PBR。ZZZ 的部位识别依据材质名及规则，不保证特殊命名自动分类正确；SDF 默认关闭。

内置 PBR 分析窗口以黄色标出名称未识别、规则冲突或资源缺失，允许选择类型并沿用原图、匹配唯一同名辅助图；服装用途名和机械“身体”等弱名称仍可能需要手动确认。自动鼻部散射遮罩在着色 v9 中增加下限，减轻多个角色的集中暗斑；源贴图、几何法线或真实遮光形成的局部明暗仍保留。眼白、虹膜及眼部高光默认带微弱可调自发光，熄灯时允许这些眼层可见；将自发光强度设为 0 可关闭。

半透明布料在着色 v9 中接入 Cloth/Fuzz，仍保留源 alpha、MatCap 和法线，因此不能保证每件源服装都直接获得柔和布感。牙齿使用原图和釉质表面，口腔阴影可能使其发灰；分类修正不会将牙齿强制涂白。详细参数与适配边界见 [角色 PBR](CHARACTER_PBR.md)。

描边宽度按槽位控制，每顶点 edge scale 尚未写入遮罩。极薄表面、特殊法线和透明面片检查实际画面。

部分角色曾在播放动画时出现刘海翻转：接近单位缩放的浮点误差经 FBX 矩阵换算后，被放大成骨骼旋转偏差。当前动画导出会把三轴均距 1 不超过 0.0001 的骨骼缩放归一，自动与手动导出均生效；不修改原 PMX、网格或法线。明显缩放、镜像和隐藏用的零缩放保留。旧任务已完成的 FBX 继续复用，应用此修正需新建导出任务。

轮廓细分仍需检查重叠衣物：GenZ 的丝袜顶点与身体重合，按材质分别处理会改变两层相对位置；历史轻度平滑对照出现新增露肤，一级细分灰材质对照也有层间遮挡变化，不能推广为所有角色外观均通过。新建内置PBR任务默认仅焊接＋加权法向，细分关闭；旧身体／丝袜开关继续保留原语义，旧任务和资产不重建。新的局部和全部件修复只在独立候选中启用。固定边界及保尖不能保证任意两层内部始终保持相对位置；开放边界附近也可能保留折面。形态键NLA轨道目前明确拒绝，不能靠删除形态键完成导出。说明与独立实验入口见 [角色 PBR](CHARACTER_PBR.md#可选轮廓平滑实验)。

此前 `SubdivisionAll_v1` 中，全部件一级原生细分在 GenZ 出现裙边缺口及金属扣中心星状黑斑，保护方案更接近基线，但灰材质仍显示重叠层变化。赛车初音裤腿外侧亮条通过逐槽标色和单独隐藏确认来自原槽30“クリプトンロゴ”（Crypton Logo）独立贴片，原槽12并非来源。裤装与Logo分别细分后，曲面相对位置改变，部分白色Logo面显露；Blender导出前已存在，原Logo自发光强度为0。该历史批次只完成定位，未应用修复。证据见本地 `work/character_pbr_20261019/SubdivisionAll_v1/BrightStripDiagnosis_v1/RESULTS.md`。保尖依赖最终类型；generic 槽采用非软表面硬边规则，分类未确认时需同时复核保护范围。

此前赛车初音法线基线另存在共面Logo显示问题：原PMX的Logo槽30共189个面，与裤装对应面位置完全相同；焊接加权法向前后坐标、拓扑、UV及Blender材质节点均保留，Logo没有被修改器删除。该批次UE按Alpha归为masked。独立CPU诊断仅将Logo外移0.1mm，完整图案恢复；当时只作定位，未验证UE动画表现。此项属于共面贴片转换兼容问题，不能将基线不可见视为正常遮挡。历史证据见本地 `work/character_pbr_20261019/SubdivisionAll_v1/LogoBaselineDiagnosis_v1/RESULTS.md`。

独立 `SurfaceRepair_v1` 候选现已在三组中恢复完整Logo及原Alpha，按宿主同一曲面处理GenZ身体／丝袜叠层，未再出现历史大块显隐带。六组数据链路通过；A／B在已检查机位与姿态通过。两个全部件C仍待复核：正面头发的碎裂高光改善，侧面仍有细碎亮带，GenZ肩袖接缝暗线更明显；不能把编译成功计作全面外观通过。这些修复未自动用于日常任务或旧资产。

贴层自动绑定目前要求整槽三角面共面、蒙皮及全部形态键兼容；不同三角化、非共面、独立运动、共享原顶点或多个宿主会拒绝并标注。几何用途结合名称、物理类型和骨骼／位置证据；未知骨架、弱名称、同槽混合用途仍需手动确认，普通名称无法证明任意槽都能安全细分。细分最大增至约5.4倍顶点、6倍三角面，并可能移动非保护区域；保尖不等于保持所有内部曲面。完整证据与剩余问题见本地 `work/character_pbr_20261019/SurfaceRepair_v1/RESULTS.md`。

## 局部修改和恢复

局部材质切换只处理能匹配转换记录的槽位。应用与撤销都检查实际绑定；后续人工改动导致状态不同，会拒绝覆盖。操作前先保存关卡与资产。

恢复需要原任务记录及素材，不能只凭保存的配置恢复全部中间结果。源文件改变后另建任务。

## 平台、插件与性能

面向 Windows x64，源码桌面环境支持 Python 3.11/3.12，目标 UE 5.8.x。原生插件需匹配实际引擎 BuildId，同为 5.8 的构建也可能不兼容。

大场景的几何、光追、体积与输出配置会共同影响 GPU 负担，测试通过不保证任意工程都能稳定渲染。设备移除时保留日志，按 [显存与画质](MRQ_MEMORY.md) 缩小复现。

MMD 烘焙需要登录且未锁定的 Windows 桌面。自动检测安装目录只搜索有限位置，特殊路径手动选择。

长动作确认载入后，上游 MMD 仍可能需要数秒到数十秒应用关键帧；日志会显示“正在应用角色动作”，等原生加载命令处理完毕后再准备 AVI 导出。不会固定等待十秒，也不执行额外的 60 帧预烘焙。导出脚本的第 0 帧回执确认本次烘焙已经开始；若已识别的动作确认框迟到至 AVI 阶段，会保留失败记录，从干净进程重试本角色一次。再次交叉或未知弹窗仍会停止。

若出现 `MMDBridge Detailed Error Report`，任务的 `mmd_full/error_dialogs.json` 会保存弹窗正文。进度文件被读取时，Windows 可能暂时拒绝替换；适配脚本会短暂重试，持续无法写入仍会报错并保留记录。

角色双 FBX 回读以 0.1 毫米为骨骼位置基准。远离原点的配件骨骼会放大单精度矩阵换算误差；超出基准、但仍在坐标精度预算（32 个 float32 刻度）内时，会以黄色警告继续，记录角色、骨骼、帧号和偏差。明显超差、非有限数值、缺少骨骼或动画仍会停止。警告保存在回读回执和角色清单中，并传递到多角色清单与 UE 报告；恢复任务时不会把失败或文件已改变的回执当成成功。

MMM 和不烘焙物理的 Blender / FBX 已弃用，保留兼容入口。详细说明见 [旧流程](LEGACY_FBX.md)。

反馈时附软件版本、操作步骤、相关日志和同帧画面；不要附带无权公开的素材。
