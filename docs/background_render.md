# 使用已保存 MRQ 预设进行后台渲染

打开工具的“场景还原”页面，选择已转换任务的 `job.json`。

1. 先在 UE 保存关卡、序列、渲染预设，然后关闭目标工程的编辑器。
2. 在“后台渲染预设”中选择已有资产，或粘贴内容浏览器中的“复制引用”。
3. 选择“按预设范围”或“只渲染一帧”。前者保留预设自定义范围；未设置范围时使用完整序列。
4. 可选输出父目录；每次创建独立子文件夹。留空时位于任务目录的 `renders/Render_…/output`。
5. 点击“后台渲染（不打开编辑器）”。页面显示进度、输出位置和日志路径。

“停止后台渲染”只停止本次工具启动的 UE 渲染进程，并保留已写出的文件。关闭工具也会停止当前后台任务。它不会自动关闭用户的 UE 编辑器。

程序启动 `UnrealEditor-Cmd.exe -game -RenderOffscreen`，由 UE 原生 MRQ InProcess Executor 处理已保存的关卡和序列。运行时没有编辑器世界；仍需要 GPU 和 UE 运行时资源。这会减少同时保留编辑器场景的负担，不构成显存占用或渲染稳定性的保证。

选中的预设被复制到内存中的任务，源资产不保存、不改写。采样、抗锯齿、电影级质量、控制台变量、颜色和已存在的渲染／输出设置全部沿用预设。仅补齐缺少的渲染 Pass 和文件输出（PNG）。输出位置指向本次独立目录；单帧模式临时覆盖帧范围。

工具保存 `plan.json`、`runtime.json`、`result.json`、`unreal.log` 和 `launcher.log`。成功需要 UE 完成回执、退出码为 0、确实写出新图片／视频，同时没有已知镜头绑定失败或 GPU 崩溃。出图成功仍保留视觉复核状态。

渲染的自动显存保护默认关闭（`render_vram_guard_enabled=false`），不会因该阈值自动停止渲染；占用采样及峰值记录继续保留，手动停止仍有效。导入／导出的保护独立保留。显式设置该字段为 true 时才使用渲染阈值保护。

命令行同样可用（默认只生成启动计划，加 `--run` 才渲染）：

```powershell
& '.\.venv\Scripts\python.exe' '.\scripts\render_ue_standalone.py' 'D:\你的任务目录' --preset '/Game/Materials/MRQ_MyPreset' --frame 1 --run
```

省略 `--preset` 时使用任务的已保存管线预设，或 `MRQ_SourceLook`。省略 `--frame` 时沿用预设范围。`--output` 指定输出父目录。`--profile` 只选择任务已保存的对应显存策略预设，不会改写所选预设。
